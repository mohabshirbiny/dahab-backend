# Data Model: Wallet Top-up (spec 009)

PostgreSQL 16. Documented first in `docs/Database schema/03_schema_ledger.sql` (new section "Top-ups"), `00_schema_full.sql` and the RLS list in `05_schema_security.sql`; one migration `2026_10_02_000010_create_topups.php` mirrors it. Money columns are `NUMERIC(18,4)` like the ledger; amounts entered by people have at most 2 decimals.

## Types

```sql
CREATE TYPE topup_method        AS ENUM ('bank_transfer', 'instapay', 'vodafone_cash');
CREATE TYPE topup_origin        AS ENUM ('notice', 'by_hand');
CREATE TYPE topup_status        AS ENUM ('pending', 'on_hold', 'credited', 'rejected', 'cancelled');
CREATE TYPE topup_reject_reason AS ENUM ('money_not_received', 'duplicate_notice', 'sender_not_accepted', 'other');
```

PHP enums: `App\Enums\TopUpMethod`, `TopUpOrigin`, `TopUpStatus`, `TopUpRejectReason` (each with an English and Arabic label for the Dashboard, customer messages and export).

| `method` | `topup_method NOT NULL` | not editable after create |

| `instapay_address` | `TEXT` | required for `instapay` (e.g. `dahab@instapay`) |
| `wallet_number` | `TEXT` | required for `vodafone_cash`, `^01[0125][0-9]{8}$` |
| `daily_limit` | `NUMERIC(14,2)` | optional, > 0, **display only** (Clarification Q5) |
| `provider_fee_percent` | `NUMERIC(5,3)` | optional, 0–100, **display only** (R4) |
| `customer_note` | `TEXT` | optional, ≤ 300 chars, shown to customers |
| `sort_order` | `SMALLINT NOT NULL DEFAULT 0` | |
| `is_active` | `BOOLEAN NOT NULL DEFAULT true` | customers see active accounts only |
| `created_at`, `updated_at` | `TIMESTAMPTZ NOT NULL DEFAULT now()` | |
| `updated_by` | `UUID NOT NULL REFERENCES staff` | last editor (seed: system actor) |

Constraints:
- `receiving_account_details` CHECK — per method, the required details are non-null (R4); details of other methods are NULL.
- Trigger `trg_receiving_account_no_delete` refuses `DELETE` (FR-002).
- Index `(method, is_active, sort_order)`.
- No RLS (reference data, like `branch`).

## `topup` (a transfer notice or a hand credit)

| Column | Type | Rule |
|---|---|---|
| `topup_id` | `UUID PK DEFAULT gen_random_uuid()` | |
| `topup_no` | `BIGINT GENERATED BY DEFAULT AS IDENTITY UNIQUE` | shown as `TOP-{topup_no}`; a hand credit reserves it with `nextval()` so the ledger memo can name it; never changes (guard trigger) |
| `customer_id` | `UUID NOT NULL REFERENCES customer` | immutable |
| `origin` | `topup_origin NOT NULL` | immutable |
| `method` | `topup_method NOT NULL` | |
| `reference` | `TEXT NOT NULL` | `DAHAB-{display_ref}` at creation; immutable |
| `claimed_amount` | `NUMERIC(18,4)` | notice only; > 0, 2 decimals; immutable |
| `notice_account_id` | `BIGINT REFERENCES receiving_account` | the account the customer said they sent to (notice only) |
| `notice_fee_percent` | `NUMERIC(5,3)` | notice only, 0–100; that account's `provider_fee_percent` when the notice was filed — a display-only snapshot, the basis of `expected_amount`; immutable (added 2026-09-30) |
| `receipt_ref` | `TEXT` | private storage key; NULL when none |
| `receipt_mime` | `TEXT` | set iff `receipt_ref` is set |
| `status` | `topup_status NOT NULL DEFAULT 'pending'` | see state machine |
| `submitted_at` | `TIMESTAMPTZ NOT NULL DEFAULT now()` | immutable |
| `hold_note`, `held_by` (staff), `held_at` | | set while `on_hold`; kept (last hold) after un-hold |
| `reject_reason` | `topup_reject_reason` | set iff `rejected` |
| `reject_note`, `rejected_by` (staff), `rejected_at` | | set iff `rejected` |
| `cancelled_at` | `TIMESTAMPTZ` | set iff `cancelled` |
| `credited_amount` | `NUMERIC(18,4)` | set iff `credited`; > 0, 2 decimals |
| `receiving_account_id` | `BIGINT REFERENCES receiving_account` | where the money arrived; set iff `credited` |
| `credit_note` | `TEXT` | required when by hand, or when `credited_amount ≠ claimed_amount`; ≤ 1000 chars |
| `arrival_reference` | `TEXT` | the provider's transaction reference for the arrival (bank / InstaPay / Vodafone Cash), ≤ 100 chars; optional, **required by the application for any credit (match or by hand) while the customer is suspended** (spec FR-016, FR-018) — it depends on the customer's status at credit time, so it is not a CHECK |
| `credited_by` (staff), `credited_at` | | set iff `credited` |
| `ledger_txn_id` | `UUID UNIQUE REFERENCES ledger_transaction` | set iff `credited` — **at most one credit per row** |
| `updated_at` | `TIMESTAMPTZ NOT NULL DEFAULT now()` | |

CHECK constraints (R3):
- `topup_amounts` — `claimed_amount` and `credited_amount` are NULL or (> 0 and `= round(x, 2)`).
- `topup_origin_shape` — `origin = 'notice'` ⇒ `claimed_amount IS NOT NULL`; `origin = 'by_hand'` ⇒ `status = 'credited' AND claimed_amount IS NULL AND notice_account_id IS NULL AND receipt_ref IS NULL AND credit_note IS NOT NULL`.
- `topup_credited_shape` — `(status = 'credited') = (credited_amount IS NOT NULL AND receiving_account_id IS NOT NULL AND credited_by IS NOT NULL AND credited_at IS NOT NULL AND ledger_txn_id IS NOT NULL)`.
- `topup_rejected_shape` — `(status = 'rejected') = (reject_reason IS NOT NULL AND reject_note IS NOT NULL AND rejected_by IS NOT NULL AND rejected_at IS NOT NULL)`.
- `topup_hold_shape` — `status = 'on_hold'` ⇒ `hold_note IS NOT NULL AND held_by IS NOT NULL AND held_at IS NOT NULL`.
- `topup_cancelled_shape` — `(status = 'cancelled') = (cancelled_at IS NOT NULL)`.
- `topup_fee_on_notice` — `origin = 'notice' OR notice_fee_percent IS NULL` (added 2026-09-30).
- `topup_difference_explained` — `status <> 'credited' OR origin = 'by_hand' OR credited_amount = claimed_amount OR credit_note IS NOT NULL`.
- `topup_receipt_pair` — `(receipt_ref IS NULL) = (receipt_mime IS NULL)`.

Triggers (R2):
- `trg_topup_guard` BEFORE UPDATE — raises `DH003` if `OLD.status IN ('credited','rejected','cancelled')`, or if `customer_id`, `origin`, `reference`, `claimed_amount`, `submitted_at`, `topup_no` or `notice_fee_percent` change.
- `trg_topup_no_delete` BEFORE DELETE — raises `DH003`.

Indexes: `(status, topup_no DESC)` for the Incoming transfers list; `(customer_id, topup_no DESC)` for the customer's list (`topup_no` rises with submission time, so it is both the order and the keyset cursor); `ledger_txn_id` unique (above).

RLS (Constitution II; `05_schema_security.sql` list): `ENABLE` + `FORCE`; policy `topup_isolation FOR ALL USING (dahab_rls_elevated() OR customer_id = dahab_current_customer_id()) WITH CHECK (same)`. Under the `ledger` scope (money service) the table is not touched.

## State machine

```
            ┌────────── cancel (customer) ─────────► cancelled
            │
 pending ───┼── hold (staff, note) ──► on_hold ──unhold──► pending
   │        │                          │
   │        ├── reject (staff) ◄───────┤ ──► rejected
   │        │                          │
   └────────┴── match (staff) ◄────────┘ ──► credited  (ledger entry)

 by hand (staff) ─────────────────────────────► credited  (origin = by_hand)
```

Final: `credited`, `rejected`, `cancelled`. Illegal move → 409 `illegal_topup_transition`.

## Ledger entry written by a credit

`PostLedgerEntryAction` with `LedgerEntry`:
- `kind = topup`, `actorStaffId = <matching staff>`, `memo = "Top-up TOP-{n} · {method label} · matched from notice {reference}"` or `"Top-up TOP-{n} · {method label} · credited by hand"` (the Wallet statement shows the memo; spec FR-021);
- lines: `bank −credited_amount`, customer `cust_available +credited_amount` (spec 008 R15: the bank's cash is `−SUM(bank)`).

## Audit events (category `money`)

| Code | When | `entity` | `before` / `after` highlights | `reason` |
|---|---|---|---|---|
| `topup.matched` | match | `topup` | status; claimed, credited, account, **customer status at credit time**, arrival reference, ledger id | credit note |
| `topup.credited_by_hand` | by-hand credit | `topup` | —; customer, **customer status at credit time**, amount, method, account, arrival reference, ledger id | credit note |
| `topup.held` / `topup.unheld` | hold / un-hold | `topup` | status | hold note |
| `topup.rejected` | reject | `topup` | status; reason | reject note |
| `topup.list_exported` | CSV export | `topup` | filters, row count | — |
| `receiving_account.created` / `.updated` | account changes | `receiving_account` | full before/after | — |

Customer submit and cancel are not audited (Part 2 §8 "audited: no"); the row itself records them.
