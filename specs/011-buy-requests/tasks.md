Every task is done except **T055** (the manual Postman /
two-app walk of quickstart.md, not done: the same scenarios are covered by the Pest feature tests and the Flutter flow

Where the code differs from the task text:

- **T012** — no `BuyRequestFactory` / `OrderFactory`: a request cannot exist without its ledger hold and position,
  so tests create requests through the API with `tests/Support/BuyRequests.php`, and orders through the seller's
  accept.
- **T013** — `DatabaseActor::queue()` never narrows an elevated caller (staff, system, maintenance): it runs the work
  as is. Found by the spec 010 concurrency test (a maintenance-scope withdrawal).
- **H2 follow-through** — the queue-scope test found that `listing_queue_move` restricts rows, not columns: a
  stranger could have edited another seller's live listing. Two column guards were added
  (`trg_listing_queue_guard`; the request guard keeps a seller to the state column).
- **T016** — notifications go through `NotifyCustomerJob` (runs as the system actor): a buyer's action cannot read the
  seller's customer row, so the recipient is loaded by the job.
- **T020 / T033** — the concurrency tests are in `BuyRequestCommitTest` (real commits on two connections: join vs
  join, accept vs leave, join vs withdraw, and the H1 commit under the plain customer scope); the "50 joins" positions
  claim is covered by `DepositReconciliationTest` (strictly increasing positions per listing) and the race tests.
- **T041** — no separate `BuyRequestLeakTest`: the seller's queue and the buyer's list assert the absence of the
  other party's id, name, phone and email (`SellerAnswerTest`, `LeaveQueueTest`).
- **T052** — notifications are asserted in each story's test (seller on new request; buyer on accepted, not chosen,
  declined, expired, withdrawn, seller suspended, free again; both on staff cancel) rather than in one file.
- **T042** — OpenAPI generated (105 paths, all 7 new); the local buy-request seeder was not written.
- **Expiry clock** — the sweep compares deadlines on the application clock (Cairo, like the database) so tests can
  travel in time.
- **Errors at COMMIT** — a deferred trigger fires in `commit()` and PDO raises a bare `PDOException`; it is mapped to
  the same domain codes as a `QueryException`.
- **Existing tests adjusted** — pinned lists (permissions +`order.cancel`, audit categories +`orders`, settings 25,
  route count 97, OpenAPI paths and schemas, listing/market keys, review counts) and the ledger tests that used
  made-up `order_id`s (the FK now exists) or truncated ledger tables without CASCADE.
- **Flutter** — the piece page's reload after an action never ran (`setState(() => _future = _load())` returns a
  Future, which Flutter rejects inside the async handler); fixed with a block body. Orders: the buyer's requests lead
  the list (`ApiOrdersRepository`); the seller's Accept / Decline live on their own piece page rather than on an
  Orders card.
